LinkBridge 联桥 · 公测使用说明书

版本：0.0.4-beta.1 · 发布批次：20261107

适合朋友试用的局域网双机协作公测版。请先用无关紧要的测试文件走完本文末尾的验收表，再用于日常工作。每组朋友生成自己的配对文件；发行包不含任何人的账号、密码或配对密钥。

1. 这版可以做什么

项目 公测范围
电脑组合 一台 Windows 11 x64 + 一台 macOS 15 或更新版本的 Apple Silicon Mac
键鼠方向 键盘、鼠标连接 Windows，用它们控制已配对 Mac；Mac 自己的输入设备可用于本地操作和恢复
屏幕布局 两端可读取各自屏幕，选择一块 Windows 屏和一块 Mac 屏建立一条接缝，可设上、下、左、右
剪贴板 双向文字和 PNG 图片；不保证所有软件专有剪贴板格式互通
文件 双向文件、文件夹复制粘贴；源文件保留，不是跨机剪切
文件拖放 Windows 到 Mac Finder 的辅助功能，首次先用复制粘贴验收；反向直接拖放不在本轮范围
无需安装 普通用户不需 .NET、Python、PowerShell 7、FFmpeg 或第三方音频驱动；包内已有 .NET 运行时

音响、摄像头、麦克风、应用窗口跨屏、磁盘挂载、任意平台组合、Linux、Intel Mac、Windows ARM 和高级多机工作区不属于本次公测承诺。源码及界面中可能仍存在实验入口，请保持关闭。新用户默认关闭自动音频和本机相机、麦克风共享；已有用户升级时保留原偏好，不擅自重置。

2. 解压后如何选择

完整解压总包，不要在压缩软件的预览窗口里直接运行。

  • 自己安装：按下文分别安装 01-Windows 和 02-macOS，然后在 Windows 生成一次配对文件。
  • 让 WorkBuddy、Codex 或其他本地 agent 安装：把完整解压目录交给 agent，复制 04-Agent/给Agent的安装指令.txt 中的文字。agent 先读 04-Agent/AGENTS.md，核验文件，再运行对应平台脚本。
  • 查看说明：双击 03-说明书/LinkBridge用户说明书.html，浏览器离线打开，可搜索、打印或另存 PDF。Markdown 为同内容的纯文本版本。
  • 需要改源码：05-源码 单独附源码 ZIP。安装使用不需要解压或编译源码。

总包里的 SHA-256 清单用于发现损坏和文件变化，不等于发布者数字签名。请从给你发包的朋友处核对总 ZIP 的 SHA-256。不要转发自己生成的配对文件到公开群、网盘公开链接或代码仓库。

3. 安装前准备

  1. 确认 Windows 为 64 位 x64，Mac 的“关于本机”显示 Apple M 系列芯片。
  2. 两台电脑连接同一可信局域网，避免访客 Wi-Fi、开启客户端隔离的无线网络；测试期间不要锁屏或休眠。
  3. 记录两台电脑各自的局域网 IPv4。Windows：设置 → 网络和 Internet → 当前连接属性；Mac：系统设置 → 网络 → 当前连接 → 详细信息。不要把 127.0.0.1、VPN 虚拟地址或公网地址填进去。
  4. 若已有 LinkBridge，先退出两端，并记住当前安装位置。升级不会删除配置和配对身份；不要同时开多个位置的副本。
  5. Mac 的权限与 Windows 防火墙按系统提示由本人确认。安装脚本不会关闭系统防护，也不会安装驱动或要求重启。

4. Windows 手动安装

  1. 打开 01-Windows/LinkBridge-0.0.4-beta.1-Windows-x64-Setup.exe。
  2. 阅读公测说明，选择专用目录。默认是 %LOCALAPPDATA%\Programs\LinkBridge，普通当前用户安装，无需管理员权限。
  3. 安装完成后，从开始菜单 → LinkBridge 打开软件、首次配对助手和用户说明书。
  4. 如果桌面原来已有指向其他目录的 LinkBridge 快捷方式，安装器会保留它。此次新安装请从开始菜单打开，并核对设置页显示 0.0.4-beta.1。不要误把旧入口当成公测版。
  5. 如 Windows 提示未识别发布者，本包确实尚未做 Authenticode 签名。先核对来源和 SHA-256，再由你决定是否允许本次运行；不要关闭杀毒或全局 SmartScreen。
  6. 如果弹出防火墙提示，只在你信任的专用网络允许此安装位置的 LinkBridge。发现成功而文件传不过去时，仍要检查防火墙是否允许实际程序。

静默安装供 agent 使用，等同于当前用户安装，不会自动启动或自动授权：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\04-Agent\Agent-Install-Windows.ps1"

这里的 Bypass 仅作用于这个 PowerShell 进程，不改变系统永久执行策略；单位策略可能仍禁止运行。脚本失败时保留错误信息，使用可见安装器查看原因，不要绕过组织管理。

5. Mac 手动安装

  1. 双击 02-macOS/LinkBridge-0.0.4-beta.1-macOS-arm64.zip 解压。得到 LinkBridge-macOS 文件夹，保持 Install.command 与 LinkBridge.app 相邻。
  2. 退出已有目标应用。打开终端，输入 sh 和一个空格，把 Install.command 拖入终端，再按回车。这样不依赖解压软件是否保留脚本执行权限。
  3. 成功后应用位于你自己的 ~/Applications/LinkBridge.app。Finder → 前往 → 前往文件夹，输入 ~/Applications，打开该应用。
  4. 本包采用 ad-hoc 签名，尚无 Developer ID 和 Apple 公证。若 macOS 阻止打开，先核对来源和清单，再自行按系统设置 → 隐私与安全性中的针对该应用的“仍要打开”流程决定。公司受管理设备可能不允许。
  5. 安装器验证应用签名、平台和版本；同一包重装会保留旧应用备份。若提示已有应用签名身份不同，它会停止，而不是强行覆盖。 保留旧版和配置，把提示交给提供软件的朋友处理，不要重签已有应用、清除权限库或关闭 Gatekeeper。
  6. 安装脚本只安装到用户 Applications，不会替换另一位置（例如桌面）的已授权应用。请只开准备使用的一个副本。

Apple 官方说明：在 Mac 上安全打开 App。系统界面的中文名称可能随系统版本略有不同。

6. 首次配对：只生成一次，分别导入

在 Windows 生成

  1. 开始菜单 → LinkBridge → 首次配对助手。也可在总包 04-Agent/配对工具 运行 打开配对助手.cmd。
  2. 填 Windows 与 Mac 各自的局域网 IPv4，不能相同。
  3. Mac 宽高填“逻辑显示尺寸”；缩放显示时它不一定是面板物理像素。暂不确定可保留初始值，连接后立即到屏幕布局读取真实屏幕并保存，再测试穿越。
  4. 点击“生成配对文件并打开文件夹”。默认存于 %LOCALAPPDATA%\LinkBridge\PairingProfiles\时间-随机值。
  5. 同一目录中 windows.settings.json 和 mac.settings.json 共享一个新生成的配对密钥。不要在另一端另生成一套。本包没有预置公共密钥。

导入 Windows

完全退出 LinkBridge，双击生成目录中的 Install-Windows-Profile.cmd。成功后原有配置会先备份，配对角色和对端地址会更新，已有名称、其他共享偏好和未知配置字段会保留。

导入 Mac

把刚生成的同一私有配对目录通过你信任的途径传给这台 Mac。退出 LinkBridge，在终端输入 sh 加空格，再拖入 Install-Mac-Profile.command，回车。脚本把 Mac 配置导入 ~/Library/Application Support/LinkBridge/settings.json 并备份旧配置。

agent 可以调用配对助手的无界面模式，不应把配置内容或密钥打印到聊天：

# 把两个示例地址换成你们的真实局域网地址；输出目录必须尚不存在。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\04-Agent\配对工具\Pairing-Assistant.ps1" -GenerateOnly -WindowsAddress "192.168.10.20" -MacAddress "192.168.10.21" -OutputDirectory "$env:LOCALAPPDATA\LinkBridge\FriendPairing"

导入配置会改变当前配对对象；已有正常配对的升级用户跳过这一步。换朋友、换电脑或明确重新配对时才生成新的一套。

7. Mac 权限与首次连接

  1. 打开两端新安装的软件。Mac 如出现本地网络访问提示，允许它访问你正在使用的可信局域网。
  2. Mac 系统设置 → 隐私与安全性 → 辅助功能，添加或启用实际安装的 ~/Applications/LinkBridge.app。这用于接收键鼠控制。
  3. 系统提示需要退出重开时，退出并重新打开同一个应用。不要给名称相同但路径不同的旧副本授权。
  4. 点击“一键连接”，检查键鼠连接状态。出现在设备列表不等于控制链路已经建立。
  5. 本轮基础功能无需相机、麦克风、录屏或完整磁盘访问权限。按实际文件访问需要处理系统提示，不要为“省事”批量放开所有权限。
  6. 先配置下一节的屏幕布局，再进行键鼠穿越。

agent 能完成文件校验、安装、配对生成和导入，并定位权限页面；系统安全确认和辅助功能授权仍须本人在真实提示中完成。一个只运行在 Windows 上、没有 Mac 访问能力的 agent 不能替 Mac 完成安装；在 Mac 上再运行对应 agent 或手动完成即可。

8. 设置屏幕布局

  1. 任一端主界面点击“屏幕布局”，或按 Ctrl + Shift + L。
  2. 点击“识别两端屏幕”，对照显示器上的编号。蓝色 Mac 卡片代表待连接的目标屏幕。
  3. 选择一块 Windows 接入口屏幕、一块 Mac 目标屏幕。把 Mac 卡片拖到 Windows 屏幕的上、下、左或右外侧，松手自动吸附；也可以使用下拉框。
  4. 看绿色接缝是否符合实际摆放。Windows 自己两块屏的内部接壤边不建立跨机入口。
  5. “可穿越范围”决定接缝中央允许通过的长度；“边缘停留”可选立即、150、300、500 毫秒。首次建议 100% 和 150 毫秒，误触时缩小范围或加长停留。
  6. 点击“保存并应用”或 Ctrl + S。连接可能短暂重建；确认界面显示成功再测试。
  7. 在另一端改过布局后，点击“刷新屏幕”读取最新设置。刷新会丢弃尚未保存的拖动。
  8. 接入/拔掉显示器、改变显示模式后，软件可能暂停穿越并要求刷新确认。重新选择并保存，不要盲目沿旧接缝移动。
  9. “恢复上一套布局”回到前一次有效布局；关闭窗口不会应用未保存的修改。

当前版本每次只建立一条跨机接缝，不会把全部 Mac 多屏合并成一个任意穿越的大桌面。多块真实 Mac 显示器和所有混合 DPI 组合仍需朋友按自己的设备验证。不要打开高级多机工作区来修复普通双机连接。

9. 键鼠使用与返回

键鼠连接 Windows，不按住按钮或修饰键，把指针持续推向绿色接缝，满足停留时间后进入 Mac。键盘输入跟随当前控制位置。沿 Mac 对应的返回边缘移回 Windows；例如 Mac 位于 Windows 下方，向上返回。

紧急返回：Ctrl + Alt + M。 第一次测试先验证这个组合键。断线恢复也应检查远端按键已释放。若异常，使用 Mac 自己的键鼠退出软件；不要反复在重要编辑窗口里试按。

普通按住鼠标或键盘键的拖动不会自动切换控制。文件拖放使用独立通道。常用编辑快捷键有映射，但不同输入法、键盘布局和应用快捷键需要实际试用；不要把系统登录、安全确认或锁屏界面视为支持的远程控制场景。

10. 文字与图片剪贴板

在“跨屏取材”中启用共享，在一端复制短文字，等状态就绪后在另一端粘贴。Windows 使用 Ctrl+C/V，Mac 使用 Command+C/V；如果使用 Windows 键盘控制 Mac，请按实际快捷键映射或菜单“粘贴”验证。

图片先用一张小 PNG 测试，在支持图片的文档/图像应用粘贴。只把文字和图片呈现正确视为成功，设备列表和预览并不证明目标应用支持该格式。文字协议上限 1 MiB，PNG 上限 32 MiB、6400 万像素；专有图层、网页富文本、带附件的邮件不保证保留原格式。

共享开启后，复制内容会发给已配对的另一台电脑。复制密码或敏感资料前可以关闭共享。应用不是剪贴板历史备份工具。

11. 文件和文件夹

  1. Windows 资源管理器或 Mac Finder 中选中小测试文件，执行“复制”。
  2. 等待对端接收完成，不要立即复制另一项打断事务。
  3. 到另一台电脑打开目标文件夹，执行“粘贴”。
  4. 确认目标文件实际出现、数量和内容正确；大文件可以比较 SHA-256。
  5. 反向重复一次。目录、中文文件名、空文件和空目录应分别验证。

接收会先写入本机 ClipboardFiles 缓存并校验，再更新系统文件剪贴板。收到缓存不等于已经保存到你想要的最终位置，还需要粘贴。 操作是复制，原文件保留。符号链接、不安全路径、云端未下载的占位文件和不可读文件可能被拒绝。

文件传输失败时，查看状态，确认磁盘可写和剩余空间，重新复制整个测试批次；没有承诺断点续传。不要把半成品当作完成。成功缓存可能跨重启保留，确认文件已落到最终目录后，退出软件再清理旧缓存。

Windows → Mac Finder 直接拖放是辅助入口：Finder 先打开可写目标目录，Windows 把测试文件拖过接缝，在 Finder 放下并等待保存回执。失败时用双向复制粘贴作为主要路径。Mac → Windows 直接拖放不在本轮承诺内。

12. 每天使用、地址变化与重连

每天打开两端固定安装位置的软件，不需要重复生成密钥。断网、休眠或退出后恢复，查看连接状态，必要时重新点击“一键连接”。鼠标、剪贴板、文件是不同通道，需要分别确认。

若路由器换了电脑地址，先确认当前两端 IPv4。不要无原因重新生成密钥。可以用配对目录里的同一组配置更新对应的 allowedControllerAddress 后再导入，保留原 inputPairingSecret；不熟悉 JSON 时让 agent 在本地备份后处理，不输出密钥。单位网络、访客 Wi-Fi 或 VPN 路由阻断时联系网络管理员。

参考端口：发现/手动连接 UDP 45678，键鼠 TCP 45680，文件 TCP 45686，文字/PNG 剪贴板 TCP 45687，屏幕布局 TCP 45691。仅排障时使用这份表；优先按程序允许可信专用网络，不开放公网端口，不做路由器端口转发。

13. 更新、卸载与恢复

Windows

退出软件，在原客户安装目录运行新版安装器。重复安装会备份旧程序，备份位于 %LOCALAPPDATA%\LinkBridge\InstallBackups。用户设置位于 %APPDATA%\LinkBridge。卸载通过 Windows 已安装的应用或安装目录 Uninstall.exe；会保留配对、用户配置、缓存、备份及用户自行添加的文件。

回退时先退出软件、备份当前安装目录，再把明确对应的旧程序备份恢复到原安装位置；不要把两个版本交叉覆盖。恢复后核对实际启动路径和版本。

Mac

同签名要求的同一包重复安装会把旧应用保留为 ~/Applications/LinkBridge.before-时间-进程号.app。若未来包的签名要求改变，安装器会拒绝覆盖；这属于明确的公测升级限制，请联系提供软件的朋友，不能承诺自动无感升级或权限自动继承。

手动卸载：退出，Finder 中把本次安装的 ~/Applications/LinkBridge.app 移到废纸篓即可；应用数据默认保留。恢复旧版：确认两个应用都退出，先另存新版，再将明确选择的旧备份改回原应用路径。不要重签原包。

Mac 设置位于 ~/Library/Application Support/LinkBridge，Windows 设置位于 %APPDATA%\LinkBridge；settings.before-pairing-*.json 是导入前备份。恢复配对需同时核对两端密钥匹配，不要把甲朋友的配置给乙朋友。

15. 朋友首次验收与反馈

按顺序做，失败一项先停止并记录，不要在真实工作文件上反复尝试：

  1. 两端设置页均显示 0.0.4-beta.1，确认启动路径。
  2. 发现、配对和一键连接成功；Mac 权限给到正确应用。
  3. 屏幕识别、选择、拖动、保存及恢复上一布局成功。
  4. 按自己实际摆放的接缝进入/返回，紧急返回可用；测试点击、短文本输入、滚轮。
  5. 两个方向复制短文字和小 PNG，实际粘贴结果正确。
  6. 两个方向复制中文名小文件、空文件和嵌套目录，实际粘贴并核对内容。
  7. 退出一端后，本机控制正常；重开后连接与复制粘贴恢复。
