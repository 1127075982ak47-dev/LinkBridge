# LinkBridge 0.0.4-beta.1 · 本地 agent 安装交接

本文件适用于 WorkBuddy、Codex 及其他获得用户授权的本地电脑 agent。目标是安装现成公测包，不需要重写软件、编译源码或接入开发者电脑。先读取同包 `03-说明书/LinkBridge用户说明书.md` 和 `06-测试记录/测试报告.md`。

## 范围与原则

- 支持一台 Windows 11 x64 主控、一台 macOS 15+ Apple Silicon 被控。输入设备连接 Windows；只设一条屏幕接缝。
- 本轮限键鼠、屏幕布局、文字/PNG 剪贴板和双向文件复制粘贴。不要为了安装基础功能装 FFmpeg、音频驱动、虚拟相机、Deskflow 或开放公网端口。
- 安装不需要激活码、账号密码、开发者 SSH 密钥、云服务密钥。包内不应出现这些信息。
- 所有路径以当前解压目录和当前用户目录计算。不要使用软件开发者电脑上的固定路径或 IP。
- 仅操作用户授权的电脑。无法访问另一端时，明确分出“本机已完成”和“另一端待执行”，不要假装双端安装成功。
- 保留配置、配对身份及现有应用备份。升级时已有配对可用就不重新生成密钥。
- 不输出 settings.json 内容、密钥或剪贴板内容到聊天、日志或工单；只报告布尔状态、路径、版本和必要错误。
- 禁止关闭 Gatekeeper/SmartScreen/防火墙，禁止批量清除隔离属性、操作 TCC 数据库或擅自重签 Mac 应用。系统确认留给使用者在实际页面完成。

## 1. 只读预检

1. 找到总包根目录：有 `PACKAGE-MANIFEST.json`、`SHA256SUMS.txt` 以及 `01-Windows` 等目录。
2. 确认系统与架构；读取现有安装位置、版本，确认是否有已运行的 LinkBridge。不要终止无关程序。
3. Windows 执行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<总包>/04-Agent/Agent-Install-Windows.ps1" -ValidateOnly`。
4. Mac 执行 `sh "<总包>/04-Agent/Agent-Install-Mac.command" --validate-only`。
5. 清单失败立即停止，重新取得完整原包；不要通过修改清单来让验证通过。SHA-256 是完整性检查，不是发行者签名，首次来源由用户确认。

## 2. 安装

Windows：运行上述命令但去掉 `-ValidateOnly`。可用 `-InstallDirectory "明确的专用目录"` 指定位置。脚本等待安装器结束、检查退出码并逐项核验实际安装文件。默认 `%LOCALAPPDATA%\Programs\LinkBridge`；会创建开始菜单，保留指向别处的原桌面快捷方式。

Mac：运行上述命令但去掉 `--validate-only`。默认 `~/Applications/LinkBridge.app`，执行严格签名检查。同一包重复安装会备份；不同签名要求会拒绝。出现拒绝就保留原应用并报告，不能当作普通错误强行覆盖。不要安装到用户桌面的已授权旧副本上。

如需要退出应用，优先请应用正常退出；若提示未保存工作或无法正常退出，报告实际阻塞。不要为了安装全局杀所有同名进程。

## 3. 一次配对

1. 在两台电脑分别读取当前可信 LAN IPv4，排除回环、VPN、虚拟网卡地址；多个候选无法确定时向用户询问实际网络。
2. 如果是首次使用，在 Windows 运行 `04-Agent/配对工具/Pairing-Assistant.ps1 -GenerateOnly -WindowsAddress <实际WindowsIP> -MacAddress <实际MacIP> -OutputDirectory <用户私有目录下的新目录>`。使用 Windows PowerShell 5.1 即可。不要在包目录或源码仓库内生成私有配置。
3. 这一步只执行一次。两端必须使用这一组生成的配置；不要分别生成不同密钥。
4. 退出两端 LinkBridge。Windows 执行生成目录里的 `Import-Windows-Profile.ps1`，Mac 通过用户授权的传送方式接收同一组后执行 `sh Install-Mac-Profile.command`。
5. 若只能控制一台机器，将另一端必须执行的准确文件、步骤和待办告诉用户；不要请求开发者的远程账号来代替。
6. 保留生成目录的私密性。导入不会删除原设置，会生成备份。更新对端 IP 应保留原密钥，不需要重新配对。

## 4. 系统确认及启动

1. 启动固定安装位置。Mac Gatekeeper、辅助功能、本地网络访问等真实确认由使用者完成；可以定位设置页面，不能绕过。
2. 防火墙只允许此应用在可信专用网络，涉及系统提升时说明目的并等用户授权；不要扩大到所有公网网络。
3. 核对两端设置页为 `0.0.4-beta.1`，查看实际运行文件，而不是只看安装器文件名。
4. 点一键连接，打开“屏幕布局”识别两端屏幕，按用户实际摆放设置和保存。不要替用户猜永久布局；未知时可停在连接成功、待用户选择布局。
5. 紧急返回 `Ctrl+Alt+M`，先用空白测试窗口验证。

## 5. 验收与停止条件

- 核验安装文件、实际启动、版本、配对双方一致和连接状态。
- 用户允许时用专用临时测试目录检查双向短文本、小 PNG、中文小文件、空文件及嵌套文件夹。确认粘贴到目标目录后再报告完成。
- 不读取或发送用户已有剪贴板的敏感内容；测试会替换剪贴板时先告知，避免干扰正在编辑的工作。
- 记录实际通过、失败、待用户授权、未测四种状态。协议探针不等于实物操作验收。
- 签名冲突、清单不符、用户拒绝权限、架构不支持时停止相应步骤；保留旧版和配置，报告原因与下一步。

## 6. 交付回报格式

```
版本：0.0.4-beta.1
Windows：实际安装路径 / 实际版本 / 启动结果
Mac：实际安装路径 / 实际版本 / 签名检查 / 权限状态
配对：已有身份保留 或 新配置已分别导入（不显示密钥）
布局：实际选择的两块屏、方向、范围、停留
已测：逐项写结果
未测或待用户：明确列出
备份：本机路径
失败：原始错误的必要片段，移除个人数据
```

卸载和回退按用户说明书第 13 节。不要删除用户数据或备份来“清理干净”。源码仅供后续开发，不作为安装前提。
